# Weather to Travel

**The forecast for your whole drive.** Pick a start, a destination and a departure time. Weather to Travel finds the route, works out when you'll reach each town along it, and pulls that town's forecast for that hour. Then it scores the drive and shows the best time to leave in the next 72 hours.

A ground-up rebuild of the original [Weather-to-travel](https://github.com/mykolyn/Weather-to-travel) bootcamp project.

## What it does

- **Arrival-time forecasts.** The route is split into up to 15 checkpoints. Each one is matched to the hourly forecast for the moment you'll pass through it.
- **Road score (0–100).** Rain, snow, ice (freezing temps plus moisture), thunderstorms, fog and visibility, and wind gusts are combined into one score with a plain-language verdict.
- **When to leave.** A 72-hour bar chart scores every possible departure hour. Tap a bar, or use the arrow keys, to re-plan instantly. No new network calls are needed.
- **Compare routes.** When there's a real alternative (e.g. I-80 vs US-50 to Tahoe), each route gets its own forecast and road score. Route cards are tagged "Fastest" and "Best weather", and alternatives appear as dashed lines you can click on the map.
- **Rest stops.** Choose no breaks, 15 min every 2 h, or 30 min every 3 h. Arrival times, the score and the "when to leave" chart all shift accordingly, and the breaks appear in the timeline.
- **Official alerts.** Active US National Weather Service alerts (winter storm, dense fog, high wind, flood…) are checked at every checkpoint. An alert counts only if it's in effect when you pass through. It's factored into the score and shown as a heads-up.
- **Sunrise & sunset.** The timeline marks where on the road you'll lose (or regain) the light.
- **Trip posters.** One tap renders a shareable 1080×1350 image of the drive in the site's isometric pen style.
- **Works offline.** It's an installable web app. Any trip you've opened still loads with no signal, using the last good forecast.
- **Heads-up and packing.** Ice risk, storms, crosswinds, big temperature swings, night driving, "bring a jacket", and so on.
- **Live map.** The route is coloured by the weather along each stretch, with temperature pins and popups. The map is linked to the timeline in both directions.
- **Shareable links.** Every plan is encoded in the URL.
- **Quality of life.** °F/°C toggle, light and dark mode, recent trips, "use my location", keyboard-accessible place search, and reduced-motion support.

## Data (all free, no API keys)

| Purpose | Service |
| --- | --- |
| Place search & town names | [Photon](https://photon.komoot.io/) (OpenStreetMap), with [Open-Meteo Geocoding](https://open-meteo.com/en/docs/geocoding-api) as a fallback |
| Driving routes, alternatives, per-segment travel time | [OSRM](https://project-osrm.org/) public server |
| Hourly forecast (8 days, many points in one request) | [Open-Meteo](https://open-meteo.com/) |
| Official weather alerts (US) | [National Weather Service API](https://www.weather.gov/documentation/services-web-api) |
| Basemap | [OpenFreeMap](https://openfreemap.org/) vector tiles via [MapLibre GL JS](https://maplibre.org/) |

The original app hard-coded Google and OpenWeather keys and relied on the now-defunct `cors-anywhere` proxy. This version has no secrets and no backend.

## Design

- **Type:** *Bricolage Grotesque* for display (a variable grotesque whose width and optical size are tuned per use), *Instrument Sans* for UI and body text, and *JetBrains Mono* for times, temperatures and data, styled like an instrument cluster.
- **Colour:** warm paper and ink, one signal orange (road-sign hi-vis), and a weather spectrum (sun, cloud, fog, rain, snow/ice, storm) used the same way on the map, the timeline and the glyphs.
- **Illustration:** isometric pen-and-ink drawings with ink outlines, crosshatch shading and colour only as a spot accent (the orange car and flag, yellow sun, blue rain). The hero diorama shows one road with three skies (sun over a town, cloud over a forest, rain over the mountains) while a car drives through. The "how it works" vignettes match. They're generated by `tools/build_art.py` (true isometric projection plus painter's-order sorting) and injected inline, so they follow light and dark mode.
- **Icons and motion:** pen-style animated weather glyphs (rays turn, rain falls, lightning flickers), a UI icon sprite, the route drawing itself on the map, a count-up road score and staggered reveals. All motion respects `prefers-reduced-motion`.

## Reliability

- Routing falls back from the public OSRM server to the FOSSGIS mirror (`routing.openstreetmap.de`). Place search falls back from Photon to Open-Meteo geocoding.
- Requests have time limits. A slow or failed service always ends in a clear message with **Try again**, never an endless spinner. A 45-second safety net backs this up.
- The page keeps the last good answer for each request, so trips you've opened work offline. `sw.js` caches the app's files and map tiles but deliberately doesn't relay live API calls (on iOS Safari that could leave requests hanging).

## Tests

End-to-end and accessibility tests use Playwright and axe, in desktop Chrome, a phone-sized Chrome and Safari's engine (WebKit, iPhone profile). They replay recorded API responses (`tests/fixtures/api.har`) with the clock pinned to the moment of recording, so they're fast, deterministic and don't depend on the free services being up.

```bash
npm install
npx playwright install chromium webkit   # first time only
npm test
```

They run on every push and pull request (`.github/workflows/pages.yml`), and the site only deploys when they pass. To refresh the fixtures, run `npm run serve` in one terminal and `npm run test:record` in another.

## Analytics (optional)

Privacy-friendly [GoatCounter](https://www.goatcounter.com/) support is built in but off. Create a free GoatCounter site, then put its code in `index.html`:

```html
<meta name="wtt-goatcounter" content="your-code">
```

It counts page views plus a few events (plan, switch route, breaks, poster). It sets no cookies and collects no personal data.

## Run it

It's a static site with no build step.

```bash
python3 -m http.server 8080
# open http://localhost:8080
```

**Deploy:** `.github/workflows/pages.yml` publishes the site to GitHub Pages on every push to `main` (or run it by hand from the Actions tab). One-time setup: **Settings → Pages → Source: GitHub Actions**. Live at https://mykolyn.github.io/weather-to-travel-claude/

## Structure

```
index.html            markup, UI icon sprite, hero illustration
assets/css/styles.css design tokens, layout, motion, light/dark themes
assets/js/api.js      Photon / OSRM / Open-Meteo clients
assets/js/model.js    route sampling, ETA → forecast lookup, hazard scoring
assets/js/icons.js    animated weather glyphs
assets/js/app.js      UI: planner, results, optimizer, timeline, map
assets/js/poster.js   trip poster renderer (canvas)
sw.js                 offline + install support
case-study.html       the case study
tests/                Playwright + axe tests and recorded API fixtures
tools/build_art.py    generates the isometric illustrations into index.html
```

To tweak the illustrations, edit `tools/build_art.py` and run `python3 tools/build_art.py`.
